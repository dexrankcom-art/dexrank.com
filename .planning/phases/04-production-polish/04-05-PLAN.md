# Plan 04-05: Dark Mode

## Objective

Implement dark mode toggle with system preference detection and persistent selection using next-themes library.

## Requirements Addressed

- DARK-01: User can toggle between light and dark mode
- DARK-02: Theme respects system preference on first visit
- DARK-03: Theme preference persists across sessions (localStorage)

## Context

The site already has `.dark` CSS variables defined in globals.css with the `@custom-variant dark (&:is(.dark *))` Tailwind v4 syntax. Components already use `dark:` variants throughout. This plan adds the runtime theme switching via next-themes.

Current layout.tsx does NOT have `suppressHydrationWarning` on the html element - this is required to prevent hydration mismatches. The providers.tsx currently only wraps NuqsAdapter.

Per RESEARCH.md: Use `attribute="class"` to work with existing Tailwind dark variant. The mount check pattern prevents hydration mismatches on the toggle button.

<task id="1" title="Install next-themes and update providers">

Install next-themes:

```bash
npm install next-themes
```

Update `src/app/providers.tsx` to include ThemeProvider:

```tsx
'use client';

import { ThemeProvider } from 'next-themes';
import { NuqsAdapter } from 'nuqs/adapters/next/app';

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider
      attribute="class"
      defaultTheme="system"
      enableSystem
      disableTransitionOnChange
    >
      <NuqsAdapter>{children}</NuqsAdapter>
    </ThemeProvider>
  );
}
```

Configuration explained:
- `attribute="class"`: Adds `.dark` class to html element, matching existing Tailwind `@custom-variant dark`
- `defaultTheme="system"`: Respects OS preference on first visit (DARK-02)
- `enableSystem`: Enables system theme detection
- `disableTransitionOnChange`: Prevents flash during theme switch

```tsx
  subsets: ["latin"],
});

const geistMono = Geist_Mono({
  variable: "--font-geist-mono",
  subsets: ["latin"],
});

  title: "DexRank - DEX Rankings & Reviews",
  description: "Compare decentralized exchanges with transparent rankings based on TVL, volume, and trust metrics.",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body
        className={`${geistSans.variable} ${geistMono.variable} antialiased`}
      >
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

The `suppressHydrationWarning` is REQUIRED because next-themes modifies the html element's class attribute on the client, which differs from the server render. This prevents React hydration errors.

<task id="3" title="Create ThemeToggle component">

Create `src/components/theme-toggle.tsx`:

```tsx
'use client';

import { useTheme } from 'next-themes';
import { useEffect, useState } from 'react';
import { Moon, Sun } from 'lucide-react';

export function ThemeToggle() {
  const [mounted, setMounted] = useState(false);
  const { resolvedTheme, setTheme } = useTheme();

  // Prevent hydration mismatch - server doesn't know theme
  useEffect(() => {
    setMounted(true);
  }, []);

  // Render placeholder with same dimensions to prevent CLS
  if (!mounted) {
    return (
      <div
        className="h-9 w-9 rounded-md"
        aria-hidden="true"
      />
    );
  }

  const isDark = resolvedTheme === 'dark';

  return (
    <button
      onClick={() => setTheme(isDark ? 'light' : 'dark')}
      className="inline-flex h-9 w-9 items-center justify-center rounded-md border border-input bg-background hover:bg-accent hover:text-accent-foreground transition-colors"
      aria-label={`Switch to ${isDark ? 'light' : 'dark'} mode`}
    >
      {isDark ? (
        <Sun className="h-4 w-4" />
      ) : (
        <Moon className="h-4 w-4" />
      )}
    </button>
  );
}
```

Key implementation details:
- Mount check prevents hydration mismatch (server can't know localStorage theme)
- Placeholder has exact same dimensions (h-9 w-9) to prevent CLS
- Uses `resolvedTheme` not `theme` to handle system preference correctly
- Accessible with aria-label describing action
- Uses existing shadcn-style classes for consistent styling
